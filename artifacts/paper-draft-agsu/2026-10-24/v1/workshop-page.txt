International Workshop · Call for Papers
Agentic Software Updates
AI agents that keep deployed software current: dependency bumps, framework and API
      migrations, security patches, and the checks that prove the system still runs.
Venue
Co-located with ANT and EDI 2027
Location
Delft, the Netherlands (hosted by TNO)
Dates
13 to 15 April 2027
Proceedings
Elsevier Procedia Computer Science (open access)
Scope
Updating software is becoming a supervised autonomous task
Keeping software current is one of the most common and least loved parts of
      engineering. LLM-based
agents
now do much of it: apply dependency and
      lockfile updates, migrate across breaking API and framework changes, backport security
      patches, then repair the tests and check the build.
This workshop is about doing that well, evaluating it honestly, and deciding which
      updates an agent may ship on its own. The stakes are highest for Industry 4.0,
      cyber-physical, and edge systems, where an update touches long-lived,
      availability-critical and safety-critical software.
Topics of interest
What we are looking for
Applying updates
Dependency and lockfile updates, including transitive and breaking changes
Framework and language-version migration; API breakage remediation
Security patch application, backporting, and CVE-driven updates
Update pull requests at scale: whether to apply, how, in what order
Validating and shipping
Post-update regression detection and test repair
Build, integration, and hardware or digital-twin-in-the-loop validation
Staged rollout, canary, and autonomous rollback
Provenance and supply-chain safety of agent-authored updates
Judgment and oversight
Deciding whether an update is worth the risk: end-of-life, CVE pressure, drift
Which updates an agent may merge autonomously, and which need sign-off
Cost, energy, and latency of agentic update pipelines
Benchmarks, real-repository studies, and negative results
